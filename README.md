# carrot-guide — наведення дрона на симуляторі

Закони наведення для мультикоптера — утримання точки та обліт кола. Літає в ArduPilot
SITL, команди по MAVLink, цикл керування 10 Гц. Тільки симулятор, без заліза.
Технічне завдання — [SPEC.md](SPEC.md).

## Запуск

```bash
make venv          # віртуальне середовище та залежності
make test          # 115 тестів без симулятора, ~1.6 с
make sitl-up       # збірка й запуск ArduCopter SITL у Docker (перша збірка ~15 хв)
make hold          # злетіти, дійти до точки, утримувати 60 с при вітрі
make orbit         # обліт кола радіусом 25 м
make test-sitl     # інтеграційні тести на симуляторі
make check         # швидкі тести, тоді симулятор та інтеграційні
make measure       # усі вимірювання з цього файлу
make plots         # графіки з логів
make sitl-down     # зупинити симулятор
```

Кожен польотний запуск пише CSV-лог у `logs/`; числа з цього файлу лежать у
[docs/measurements](docs/measurements) і відтворюються одним `make measure`. Готового
образу SITL немає, тому він збирається з джерел ArduPilot на тезі `Copter-4.5.7` — перша
збірка ~15 хвилин, далі з кешу Docker.

## Модулі

Межа одна — по вводу-виводу: із сокетом працює лише `link.py`, тому вся математика й
весь цикл керування тестуються без симулятора.

| Модуль | Що робить |
|---|---|
| `state.py` | стан апарата, локальна система координат NED, проєкція WGS84 ↔ NED |
| `guidance.py` | закони наведення: чиста математика, жодного вводу-виводу |
| `telemetry.py` | потік MAVLink-повідомлень → типізований стан |
| `link.py` | єдиний модуль, що працює із сокетом: команди, підтвердження, параметри |
| `runner.py` | цикл керування з фіксованим періодом, збір статистики, failsafe |
| `mission.py` | зліт, посадка, вимірювання затримки |
| `utils.py` | усе загальне без прив'язки до польоту: `Deadline`, `Command`, процентилі, парсери колонок |
| `metrics.py`, `recording.py`, `plots.py` | метрики, лог, графіки |
| `cli.py` | по одній підкоманді на кожен експеримент із ТЗ |

## Закони наведення

Обидва видають вектор швидкості в локальній системі NED; внутрішній контур швидкості
замикає автопілот. Перед видачею команда насичується обмеженнями по горизонтальній і
вертикальній швидкості.

**Утримання точки** — пропорційно-диференціальний контур: `kp` тягне до цілі, `kd`
гасить швидкість підходу.

**Обліт кола** — сума тангенційної складової, яка несе апарат по колу, і радіальної, яка
тримає відстань до центру. Ціль виноситься вперед на `lookahead_s` = 0.22 с: це виміряна
затримка реакції цієї зв'язки, а не підібраний коефіцієнт. Винесена вперед точка
прицілювання в законах переслідування зветься carrot — звідси назва проєкту.

## Вимірювання

Хост: MacBook (arm64), симулятор у Docker, `SITL_SPEEDUP=1`, home — Київ. Вітер
задається параметрами симулятора (`SIM_WIND_SPD`, `SIM_WIND_TURB`) із самого запуску.
Похибка міряється на ділянці утримання: статистика починається через 8 с після виходу на
точку, інакше в середнє потрапляє хвіст підходу. Кожен підсумок називає своє вікно
(`window`): `hold`, `post-settle` або `whole run`.

### Утримання точки

Ціль — 25 м на північ, висота 15 м, 60 с.

| | без вітру | 6 м/с | 6 м/с + пориви | 15 м/с + сильні пориви |
|---|---|---|---|---|
| середня похибка | 0.010 м | 0.010 м | 0.010 м | **0.099 м** |
| RMS | 0.011 м | 0.011 м | 0.012 м | 0.115 м |
| 95-й процентиль | 0.017 м | 0.017 м | 0.021 м | 0.206 м |
| максимум | 0.020 м | 0.020 м | 0.028 м | 0.298 м |
| час виходу на точку | 6.4 с | 6.4 с | 6.4 с | 7.1 с |

Перші три колонки однакові: контур швидкості автопілота парирує стале навантаження
нахилом, і до зовнішнього контуру доходить лише залишок. На десятихвилинному прогоні
(6 м/с із поривами) середня похибка 0.011 м — те саме, що на шістдесяти секундах.

![утримання точки](docs/hold.png)

### Обліт кола

Радіус 25 м, тангенційна швидкість 4 м/с, висота 20 м, 90 с, вітер 6 м/с із
турбулентністю. Похибка — відхилення від заданого радіуса.

| | тангенс на поточну точку | з передбаченням 0.22 с |
|---|---|---|
| середнє відхилення радіуса | 0.492 м | **0.311 м** |
| RMS | 0.493 м | 0.312 м |
| 95-й процентиль | 0.543 м | 0.368 м |
| вихід на коло | 5.9 с | 6.3 с |

Без передбачення похибка стала й однобока — коло завжди ширше заданого, бо тангенс,
порахований для поточної позиції, застаріває за час реакції апарата. Передбачення
прибирає 37% похибки; решта лишається, і всі відліки на режимі досі зовні кола.

![обліт кола з передбаченням](docs/orbit.png)

![обліт кола без передбачення](docs/orbit-nolookahead.png)

### Частота циклу

Десятихвилинний прогін, 5 999 тіків.

| | значення |
|---|---|
| задана частота | 10 Гц |
| фактична середня | 10.0000 Гц |
| джитер періоду (σ) | 0.136 мс |
| запізнення, 95-й процентиль | 0.002 мс |
| запізнення, максимум | 4.5 мс |
| ресинхронізацій / втрачених тіків | 0 / 0 |

Дедлайни абсолютні (`origin + index * period`), а останні мілісекунди періоду цикл не
спить, а крутиться в очікуванні. Скільки саме — міряє `measure_sleep_overshoot` на
старті, бо Darwin прокидає потік тим пізніше, чим довший сон: без цього кожен тік
запізнювався на ~10 мс. Останній рядок таблиці обов'язковий: ресинхронізація перебазовує
дедлайн, тому зрив показує нуль запізнення, і видно його лише за лічильником.

### Затримка «команда → реакція»

Час від надсилання цільової швидкості до моменту, коли телеметрія показує 10% від
заданої (крок 3 м/с, 6 спроб, вісь чергується).

| | значення |
|---|---|
| медіана | 222 мс |
| мінімум | 168 мс |
| максимум | 486 мс |

Величина наскрізна — канал, цикл автопілота, інерція апарата, телеметрія 20 Гц, — тому
це оцінка того, наскільки застарілі дані в циклі, а не затримка каналу. Її ж закон
обльоту кола використовує як `lookahead_s`.

### Пам'ять

Профілювання `memray` на двох тривалостях: витік видав би себе залежністю від них.

| пік heap | 60 с | 600 с |
|---|---|---|
| лог лишається в пам'яті | 17.317 МБ | 21.540 МБ |
| `--stream-only` | 17.317 МБ | **17.317 МБ** |

Приріст 4.2 МБ — це лог, який прогін тримає в пам'яті для підсумку (6 000 відліків ×
~0.7 КБ). Підсумок вимагає всього ряду одразу, тому в польотному процесі його рахувати
не можна: із `--stream-only` цикл лише пише CSV, а числа дає `carrot-guide report <log>`
потім. Решта 17 МБ — базовий рівень процесу: імпорти, pymavlink і numpy.

## Надійність

- **зліт як цикл, а не послідовність.** Холодний автопілот відхиляє GUIDED, поки не
  зійшовся EKF; скидає його в STABILIZE під час `ARM`; відмовляє на pre-arm; робить
  `DISARM` сам через ~10 с, якщо ніхто не злетів. Тому `launch()` перевіряє кожен стан
  перед кроком, який його вимагає, а причину відмови бере зі `STATUSTEXT`.
- **один читач сокета.** `recv_match` із фільтром за типом з'їдає інші повідомлення,
  тому всі очікування читають усе й фільтрують після того, як віддали повідомлення
  трекеру.
- **тайм-аут телеметрії.** Немає позицій `stale_after_s` — цикл надсилає нульову
  швидкість і падає з помилкою, а не летить за застарілими даними.
- **гальмування за замовчуванням.** ArduPilot гальмує, щойно цільові швидкості
  перестають надходити, тому прогін навмисно завершується нульовою командою.

## Тести

- **115 без симулятора**, 1.6 с: математика, парсинг телеметрії, метрики, лог, CLI, цикл
  керування на fake-апараті, послідовність зльоту на відмовах холодного автопілота.
- **`make smoke`** запускає встановлений `carrot-guide`: швидкі тести імпортують із
  `src/` і зламаного встановлення не побачили б.
- **5 на SITL** (`-m sitl`), 3 хв: зліт, утримання з вітром і без, обліт кола по всіх
  чотирьох квадрантах, затримка.
- Годинник і `sleep` у циклі — параметри, тому «десять хвилин на 20 Гц без дрейфу» — це
  звичайний швидкий тест.

## Обмеження

- лише симулятор: ні заліза, ні вібрацій, ні втрати каналу, ні реального GNSS;
- проєкція «плоскої Землі»: на сотнях метрів похибка менша за метр, на десятках
  кілометрів — ні;
- затримка включає інерцію апарата, тому це не затримка каналу;
- вітер у SITL — модель, а не аерологія;
- налаштування регуляторів і `lookahead_s` — під цю модель апарата й цю зв'язку.
