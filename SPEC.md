# ТЗ: наведення дрона на симуляторі (SITL + MAVLink)

## Мета

Навчальний проєкт для закриття двох прогалин у резюме перед співбесідою в The Fourth Law:
**MAVLink** та **алгоритми наведення й керування**. Заліза не треба — усе на софтовому
симуляторі. Результат має бути публічним репозиторієм із вимірюваннями, про який можна
говорити на технічній співбесіді.

Не мета: імітувати реальний польотний досвід.

## Обсяг

**У межах:**

- підключення до симулятора по MAVLink, читання телеметрії
- керування апаратом через MAVLink (arm, takeoff, land, задання цілі)
- власний закон наведення: утримання точки та обліт кола
- вимірювання: похибка утримання, латентність «команда → реакція», споживання пам'яті
- тести: швидкі без симулятора й інтеграційні на ньому

**Поза межами:** реальне залізо, політ надворі, комп'ютерний зір, планування маршрутів,
уникнення перешкод, GCS-інтерфейс.

## Середовище

- **ArduPilot SITL** (ArduCopter) — софтовий симулятор апарата
- **Python 3.11+**, `pymavlink` як транспорт MAVLink
- **Docker** — симулятор у контейнері, щоб запуск був однією командою. Готового образу
  SITL немає (спільнотні — застарілі й лише amd64), тому образ збирається з джерел
  ArduPilot на закріпленому тезі
- **Make** — точка входу: усі прогони локальні, по одній цілі на крок

## Функціональні вимоги

| # | Вимога |
|---|--------|
| F1 | Підключення до SITL по MAVLink, обробка `HEARTBEAT`, читання позиції, швидкості, режиму, стану батареї |
| F2 | Керування станом апарата: `ARM`/`DISARM`, зліт на задану висоту, посадка; коректна обробка відмов |
| F3 | **Утримання точки**: власний регулятор, що виводить апарат у задані координати й тримає його там при збуренні (вітер у SITL) |
| F4 | **Обліт кола**: наведення по колу заданого радіуса навколо точки, керування через `SET_POSITION_TARGET_LOCAL_NED` (по швидкості) |
| F5 | Логування телеметрії у файл + побудова графіків: траєкторія, похибка від цілі в часі |

## Нефункціональні вимоги

- **Частота циклу керування** — не менше 10 Гц, зі стабільним періодом; джитер
  вимірюється й потрапляє в підсумок прогону
- **Латентність** «команда → реакція» вимірюється й записується в README
- **Пам'ять** — профіль довгого прогону (10 хв) через `memray`, без зростання споживання
- **Тести** (`pytest`):
  - юніти на математику наведення (перетворення координат, регулятор) — без симулятора
  - інтеграційний тест на піднятому SITL: злетів, дійшов до точки, утримався N секунд
- **Прогін**: швидкі тести — однією командою в чистому клоні, без симулятора; інтеграційні
  на піднятому SITL — окремою ціллю, бо збірка симулятора довга

## Архітектура

Чотири модулі з чіткою межею — щоб математику можна було тестувати без симулятора:

```
link/       підключення MAVLink, прийом/надсилання повідомлень
telemetry/  розбір потоку в типізований стан апарата
guidance/   закони наведення (чиста математика, без вводу-виводу)
runner/     цикл керування з фіксованим періодом, логування
```

## Критерії готовності

- утримання точки: середня похибка < 1 м на 60-секундному прогоні з увімкненим вітром
- обліт кола: відхилення від заданого радіуса < 2 м
- 10-хвилинний прогін без зростання пам'яті
- увесь набір тестів зелений локально, README з графіками й цифрами

## Етапи

1. **Підняти й побачити** — SITL у Docker, підключення, друк телеметрії, arm/takeoff/land *(F1, F2)*
2. **Змусити летіти за законом** — утримання точки, потім коло; логування й графіки *(F3, F4, F5)*
3. **Довести цифрами** — тести, вимірювання латентності, профіль пам'яті *(нефункціональні)*

Кожен етап — самодостатній результат, який уже можна показати.
